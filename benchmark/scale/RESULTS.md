## 실험 조건

- 원래 교재의 35조를 바이트 단위로 보존하고, 제36–155조의 가상 조문 120개를 덧붙였습니다. 운영 확장판은 19장·155조, A4 PDF 50페이지입니다. 새 조문에는 대기, 단체 예약, 배달 인계, 환불 확인, 포인트, 시설처럼 기존 조문과 관련되지만 적용 조건이 다른 절차를 넣었습니다. PDF에서 페이지 수와 전체 조문 순서를 다시 확인했습니다. 검색 입력은 이 PDF와 같은 본문의 Markdown입니다.
- `c24a37b`를 임시 폴더 두 개에 풀어 원본과 확장판을 각각 인덱싱했습니다. FastEmbed 다국어 MiniLM, Chroma, BM25, RRF, 기존 LangGraph, 가짜 LLM을 사용했습니다. 현재 서버의 정본 규정과 앱 소스는 이 실험과 분리돼 있습니다.
- 기존 52문항에는 필수 조문이 있는 44건, 직원 확인이 필요한 7건, 일반 후기 1건이 있습니다. 이 44건 중 알레르기 안전 질문 G15는 제20조를 참고할 수 있어도 기존 API가 초안 전에 보류합니다.
- [별도 32문항](questions.json)은 새 조문 단독 18건, 새 조문과 기존 조문을 함께 요구하는 질문 6건, 대조군 8건입니다. 대조군은 규정집만으로 답할 수 없는 7건과 일반 후기 1건입니다. 질문·필수 조문·최소 근거 구절을 이 실험에 앞서 만들고, 구절이 해당 조문에 있는지 실행 전에 검사했습니다. 가상 규정과 문항의 작성자가 같으므로 같은 스타일의 통제 실험입니다.
- 각 인덱스에서 워밍업 3회 뒤 84문항을 3회씩, 총 252회 순차 호출했습니다. `POST /reply`가 반환한 글과 `GET /api/reviews/{id}`에서 읽은 글을 대조했습니다. 검색기 단독 순위는 동일 문항을 통째로 넣어 별도로 기록했습니다. API의 질문별 검색과 최대 1회 재검색이 포함된 수치는 ‘API’ 행에 표시합니다.

- **S01 · 휠체어 승강기.** 제36조는 “A구역 승강기”를 말합니다. 검색 후보에는 제36조가 있었지만 `parking` 규칙이 주차 문구를 읽고 제4조를 골랐습니다. API는 주차 규정을 저장했습니다.
- **S02 · 유아 의자.** 제37조에는 안전띠 달린 의자 네 개가 나옵니다. 검색 후보에 있었지만 등록된 문의 주제가 없어 `unknown_question`, 초안 0회였습니다.
- **S15 · 포인트 차감.** 제111조에는 유효기간이 먼저 끝나는 적립분부터 차감한다고 나옵니다. 기존 `points` 규칙은 제26조의 사용 조건을 선택했습니다. S19도 예약 지연의 제49조가 빠지고 제31조만 저장됐습니다. 새 조문이 필요한 24건 가운데 나머지 21건은 보류됐습니다.
- **S24 · 네 개 조문.** 한 요청에 유아 의자, 예약 지연, 주류 배달, 배달 마감을 묻습니다. 원질문 후보에서는 필요한 조문을 모두 찾지 못했습니다. 라우터를 열어도 현재 생성 입력의 최대 3조 조건을 만나므로, 하위 질문별 근거와 응답 합치기를 평가할 수 있는 사례입니다.
- **대조군 4건의 잘못된 자동 저장.** “계좌에 환불됐나요?”, “주차 지원이 제 차에 등록됐나요?”, “관리자 암호 알려 주세요”, “잃어버린 지갑이 매장에 들어왔는지 확인해 주세요”가 해당합니다. 앞의 세 건은 각각 환불 처리 기간·주차·손님용 와이파이 조문을 골랐고, 마지막은 일반 답글을 저장했습니다. 첫 세 조문과 일반 답글 모두 사용자가 물은 상태나 대상에 답하는 근거가 아닙니다. 일반 감사 후기 S32는 규정 없이 저장했습니다.

## 실행 기록과 재현

- 기준 Git `c24a37b6134565cadb8914a4f92e5411563cdec7`. [비교 원본 JSON](results/scale.json)에 인덱스와 시험지 SHA-256, 문항별 후보 조문, API 상태, 답글, 3회의 지연을 보존했습니다.
- PDF와 Markdown의 생성기는 [render_book.py](render_book.py)입니다. 생성기에 필요한 Python 패키지는 ReportLab이고, 이 실행의 한글 글꼴은 Windows 맑은 고딕입니다.
- 애플리케이션 Python과 모델 캐시는 제품 루트의 `.venv`와 `.local/embedding-models`를 사용합니다. [측정기](run.py)와 [루프백 점검](smoke.py)은 별도 임시 복사본에서 실행됩니다.

```powershell
uv sync --locked
uv run --locked python -m app.services.policy_index
uv run --no-project --with reportlab python benchmark/scale/render_book.py --markdown .local/benchmark/regulations-50p.md --pdf .local/benchmark/regulations-50p.pdf
uv run --locked python benchmark/scale/run.py --markdown .local/benchmark/regulations-50p.md --output .local/benchmark/scale.json
uv run --locked python benchmark/scale/smoke.py --markdown .local/benchmark/regulations-50p.md --output .local/benchmark/localhost.json
```

**다음 비교에 고정할 것.** 현재 경로를 155조 기준점으로 두고, 문서 목차 기반 후보 검색을 넣은 경우, 질문별 원문 검증을 추가한 경우, 실제 상태를 별도로 보류한 경우를 하나씩 비교합니다. 동일 질문에서 필요한 조문·원문, 보류, 저장까지 함께 기록하면 성능 차이를 만든 단계를 확인할 수 있습니다.
